# Himalaya + Mail.app IMAP (public)

**This repository is public.** Mailbox addresses, IMAP passwords, and generated profiles stay **off git**.

Installs [himalaya](https://github.com/pimalaya/himalaya) (CLI) and [himalaya-tui](https://github.com/pimalaya/himalaya-tui) on the home Macs, and can generate an unsigned Apple Mail IMAP profile for extra (non-iCloud) `mail@` accounts.

Mailbox inventory and MX live in a **private** ops repo. This tree only installs clients and materializes local config from Proton Pass.

## What is committed vs local

| Piece | Where |
|-------|--------|
| Homebrew formula `himalaya` | `brewfile.home.machines` |
| himalaya-tui (not bottled) | `scripts/himalaya-setup.sh --tui` (cargo git, pinned rev) |
| Account map (addresses + Pass **titles**) | gitignored `scripts/himalaya-accounts.local` (copy [himalaya-accounts.example](../scripts/himalaya-accounts.example)) |
| `~/.config/himalaya/config.toml` | generated locally (`0600`); `password.command` → `pass-cli`, never `password.raw` |
| Mail.app `.mobileconfig` | generated locally (`0600`); passwords injected at apply time; **delete after install** (`rm -P`) |

Suggested Pass title patterns (customize privately):

| Kind | Title pattern |
|------|----------------|
| Hosted IMAP mailbox | `{addr} (INWX Froxlor)` |
| iCloud app-specific password | `Himalaya (Apple)` |
| Gmail app password | `Himalaya (Google Mail)` |

Do **not** use the Google account login item for IMAP. Gmail app passwords need 2-Step Verification.

## Apply

```bash
# Packages (himalaya CLI)
cd ansible && ansible-playbook setup-macos.yml --limit primary --tags brew

# TUI + config.toml (skips config if the local map is missing)
ansible-playbook setup-macos.yml --limit primary --tags himalaya
# secondary: --limit secondary

# Or without Ansible:
./scripts/himalaya-setup.sh --tui
```

Copy the map once per clone (not via git):

```bash
cp scripts/himalaya-accounts.example scripts/himalaya-accounts.local
# edit addresses + Pass titles; keep gitignored
```

`pass-cli` over SSH often fails with Keychain **-25308**. Generate Mail.app profiles and run `himalaya account check` in a **GUI Terminal** on that Mac.

## Mail.app extra IMAP (`mail@` only)

Unsigned `com.apple.mail.managed` profile. `profiles` has **no** install verb on current macOS — open the file, then **System Settings → General → Device Management → Install**.

```bash
# GUI Terminal, pass-cli already logged in
./scripts/himalaya-setup.sh --mailapp

# Ansible (off by default — needs GUI Pass + a click in System Settings)
cd ansible && ansible-playbook setup-macos.yml --limit primary --tags mailapp
```

Only map rows with `mailapp=true` are included (the extra IMAP `mail@` boxes, not `spam@` / `admin@`, not iCloud, not Gmail). iCloud custom-domain addresses are identities on the Apple ID mailbox — signing into iCloud Mail is enough; do not add one IMAP account per iCloud domain.

After Mail.app authenticates: `rm -P` the `.mobileconfig` (it contained passwords). Do not leave it in Downloads or the git clone.

iPhone is **not** automated here.

## Behaviour notes

- Himalaya v2 config is first of `$XDG_CONFIG_HOME/himalaya/config.toml`, `~/.config/himalaya/config.toml`.
- Default account is the map row with `default=true` (iCloud in the usual private map).
- TUI is **one IMAP login per session** (`himalaya-tui -a name`). No unified inbox.
- Bare `himalaya` (no subcommand) starts the wizard — do not run it against the live file unless you mean to.
- Do not wire himalaya-mcp, Fastmail MCP, or IMAP inside `~/.grok/config.toml` unless asked.
- Do not auto-send mail unless explicitly asked.

## `just <domain>`: open a mailbox from anywhere

A global justfile opens one Himalaya account per recipe:

| Piece | Where | In git |
|-------|-------|--------|
| `~/.config/just/justfile` | `dot_config/just/justfile` (chezmoi) | yes, generic |
| `~/.config/just/himalaya-open.sh` | `dot_config/just/executable_himalaya-open.sh` (chezmoi) | yes, generic |
| `~/.config/just/mail.just` (0600) | generated by `scripts/just-mail-gen.py` from `~/.config/himalaya/config.toml` | **no** (holds addresses) |
| `~/.config/just/mail-aliases` (0600, optional) | copy of [`scripts/just-mail-aliases.example`](../scripts/just-mail-aliases.example), `alias = account` per line | **no** |
| zsh `just` wrapper | `dot_config/just/just-wrapper.zsh`, sourced from `dot_zshrc` and `dot_zshenv` | yes |
| fallback helper | `dot_config/just/executable_just-global-fallback.sh` → `~/.config/just/just-global-fallback.sh` | yes |

```bash
python3 scripts/just-mail-gen.py      # after any change to the Himalaya accounts
just mail                             # list the mail recipes
just <domain>                         # TUI on that domain's main mailbox
just <domain>-spam                    # one recipe per Himalaya account too
just <domain> envelope list -s 10     # extra args run the CLI: himalaya <args> -a <account>
just <domain> mailbox list
```

Recipe names: one per Himalaya account (the account name, e.g. `example-mail`), plus one per domain prefix. The domain recipe opens the personal mailbox if the domain has exactly one local-part other than `mail`/`spam`/`admin`, else `<domain>-mail`. Accounts without a `-` (`icloud`, `gmail`) only get their own name. Extra names (e.g. a personal handle for the iCloud account) go in the local `~/.config/just/mail-aliases` as `alias = account`; the generator refuses unknown accounts and names that clash with an existing recipe. No args starts `himalaya-tui -a <account>` (falls back to `himalaya envelope list` if the TUI is missing). Nothing sends mail.

**How `just <recipe>` finds the global file.** `just` only reads `~/.config/just/justfile` with `-g` / `--global-justfile`. A zsh function `just` (sourced from `.zshrc` for interactive shells and from `.zshenv` for every zsh, including `zsh -c`) calls `~/.config/just/just-global-fallback.sh`. That helper looks at the first recipe argument, including after flags such as `--dry-run` or `--show`, and runs `just -g <recipe>` only when the local justfile (or none) has no recipe of that name and the global one does. Otherwise it runs plain `just`. Tradeoff: project recipes always win, so inside a repo that has a recipe with the same name as a domain you must type `just -g <domain>`. Listing flags (`just --list`, `just --summary`) always go to the local justfile; use `just -g --list` for the global one. In bash or any shell that does not source this wrapper, use `just -g <domain>`. Set `JUST_NO_GLOBAL_FALLBACK=1` to disable the fallback for one command.
